# Read the Rotate

Booth mini game for the **Cloud9 x JetBrains: Sky's The Limit Hackathon 2026**, Category 3 (Event Mini Game).

You see a pro VALORANT round on an abstract radar, 12 to 30 seconds before the plant. You call the site with one click. Then the round plays out and shows whether you read it like a pro. Twenty rounds, about four minutes.

## How a session plays

`menu → 20 rounds → final score (initials if top 10) → menu`

Each round:

1. **Read** (6 s): the radar shows attackers (red magnets), defenders (blue magnets) and the sites. A solid magnet is a fresh position; a dotted ring with a label (`6s`) is where that player was last seen; `?` means the position is too old to trust; `x` is a dead player. The map is turned so attackers start at the bottom and the sites sit side by side above them. Dim dots behind them are the map's corridors: every cell where some player in the pack has stood, so walls and chokepoints show up without any map art (computed in the browser from the loaded pack; nothing extra is stored).
2. **Call**: click a site. No click before the LED bar runs out counts as a miss.
3. **Reveal**: the rest of the round replays at 4x speed until the bomb (white triangle) goes down. GRID only records a position when a player is in an event (median 5.6 s apart), so between two sightings the replay walks the shortest route over the corridor cells instead of a straight line through walls; one-cell gaps where nobody happened to be recorded are bridged. When no walk fits (corridors not connected in the data, or too far for the time; about 0.5% of moves) the player is not drawn through a wall: the radar parks them as a dotted "last seen" ring until the next sighting. Each kill flashes a dotted line from the shooter to the victim in the shooter's colour (from GRID's kill events), so fights are visible instead of players just dropping. The real site gets a green ring, a wrong call a red one. Next to the replay, plain facts from the data explain what was going on: who was already down and where, where the defenders stood, and who fell first after your read. No guessed reasons.

Scoring: 100 for a correct call, up to +50 for calling fast, +20 per answer in a streak. Rounds 1-6 show the radar 12-16 s before the plant, rounds 7-13 at 17-22 s, rounds 14-20 at 23-30 s, so it gets harder.

Rotates: going to the site the attackers lean toward would win most rounds, so each session mixes in real rotates, rounds where the attackers clearly lined up on one site (fresh sightings, confirmed by the later data) and then planted on another: 1 of the first 6 rounds, 3 of the next 7, 4 of the last 7, shuffled. The synthetic demo pack has fewer rotates (none early), so a demo session fills those slots with plain rounds and shows about 6 or 7. The result names them ("THEY ROTATED TO B", "YOU READ THE ROTATE"). Rounds whose read is wrong only because of stale or scattered data are left out, so a miss is never just bad data. On the pro pack a plain "go where they lean" read scores about 91% / 82% / 71% by tier without rotates.

Mouse only. The canvas scales to any screen.

## At the booth

- **Attract screen**: the menu replays a random round and shows the top 5 scores.
- **Leaderboard**: a top-10 score asks for three initials (arrows, or type them if there is a keyboard). It lives in the browser's local storage on that machine only.
- **Booth comparison**: from the 6th session on, the final score says "Better than X% of players at this booth", using every finished session's score on that machine.
- **Walk-away reset**: 30 s without a click in a game or on the final score goes back to the menu.
- **Operator keys**: `F2` fullscreen, `F4` back to the menu, `Shift+Delete` clears the leaderboard and score history (asks first).

## Run the game

Requires Node 22.18+ (the tests run the `.ts` files directly).

```bash
npm install
npm run dev      # http://localhost:8080
npm test         # game rules (plain node, no extra deps)
npm run build    # typecheck + production build into dist/
```

The game loads `public/packs/pro/scenarios.json` (built from GRID data, see below) and falls back to `public/packs/demo/scenarios.json`. The demo pack is invented: two made-up maps and 60 scripted rounds (straight hits, fakes, splits) with GRID-like sparse sightings, generated by `python pipeline/make_demo_pack.py` without reading any match data. It lets anyone play a clone or a hosted build, and the menu says "Demo rounds" when it is in use. A production build **drops the pro pack** so a hosted `dist/` never contains GRID data. For a local booth build that should keep it, run `INCLUDE_PRO_PACK=1 npm run build` and never upload that `dist/`.

## Data pipeline

The GRID data is licensed for this hackathon only and may not be redistributed, including anything derived from it. So the data repo lives **next to** this repo, and generated packs go to gitignored folders.

```bash
git clone https://github.com/cloud9esports/stl-hackathon-2026-grid-starter.git ../stl-hackathon-2026-grid-starter
python -m venv .venv && .venv/Scripts/activate      # macOS/Linux: source .venv/bin/activate
pip install -r pipeline/requirements.txt
python pipeline/inspect_series.py <series_id>       # ids are in ../stl-hackathon-2026-grid-starter/val/series.csv
python pipeline/extract_scenarios.py                # first 30 series -> public/packs/pro/scenarios.json
python pipeline/extract_scenarios.py <series_id>... # or pick series; --max-series N to change the default
python pipeline/make_demo_pack.py                   # regenerate the committed demo pack (no data needed)
python -m unittest discover pipeline                # self-check on a synthetic feed, no data needed
```

A scenario is one planted round: each player's radar track from the end of buy phase until 5 s after the plant (`[t, x, y, alive]`, `t` in seconds), which side they are on, and the site. GRID has no site field, so sites come from k-means over every plant position on that map (3 sites on Haven and Lotus, 2 elsewhere). Player names and ids are dropped.

GRID only updates a player's position when an event involves them, so tracks are sparse (median gap about 3 s, longer for quiet players). The game should show how old each dot is.

Set `STL_DATA_DIR` if the data repo is somewhere else.

## Data guard

Git hooks in `.githooks/` block commits that contain GRID data or packs built from it, and commit messages that credit AI tools as co-authors. Enable them once per clone:

```bash
git config core.hooksPath .githooks
npm run check-data   # same check, on demand
```
